# 작업 배정·정산 기능 데이터 연동 초안

## 목적

현재 `sb-work`의 업무 배정 데이터를 다음 흐름에 재사용한다.

```text
월 배정안 자동 생성
→ 관리자 예외 확인·승인
→ 담당자가 본인 배정 확인·작업
→ 담당자가 월 정산과 견적서 요청
→ 결제 담당자가 노션에서 결과 확인
→ 결제 승인·이체 완료
```

작업 결과물은 기존 노션에서 관리한다. `sb-work`에는 결과물 링크, 완료 보고, 내부 검수 기능을 추가하지 않는다.

## 활용할 기존 화면

| 업무 | 기존 화면 | 활용 내용 |
|---|---|---|
| 작업 배정 | `/admin/assignments` | 월, 지점, 담당자, 역할별 수량 배정 |
| 작업자 확인 | `/my` | 로그인한 작업자의 월별 배정 내역과 합계 |
| 담당자별 작업량 | `/admin/dashboard` | 역할 수량과 전월 대비 집계 |
| 배정안 승인 | 신규 기능 | 자동 생성 결과와 예외 항목 확인 |
| 정산 관리 | 신규 화면 | 견적서 확인, 승인, 이체 완료 |

## 현재 데이터 흐름

```text
구글 시트 또는 관리자 입력
→ assignments에 월별 지점·담당자·수량 저장
→ profiles의 담당자 계정과 *_writer_id로 연결
→ branches에서 지점명·분류 조회
→ /my에서 본인 배정만 표시
→ /admin/dashboard에서 담당자별 수량 합산
```

## 현재 필드의 사용처

### `assignments`

| 필드 | 현재 사용 | 신규 기능에서 사용 |
|---|---|---|
| `month` | 월별 배정 조회 | 자동 생성 대상 월·정산 월 |
| `branch_id` | `branches` 연결 | 배정과 청구의 업체 근거 |
| `*_writer_id` | 역할별 담당자 연결 | 작업자와 정산 요청자 식별 |
| `*_writer_name` | ID 미매칭 시 이름 표시 | 과거 데이터 보조 식별값 |
| `*_quantity` | 역할별 작업량 | 청구 수량 스냅샷 |
| `status` | 신규·변경·중단·보류 | 정산 상태로 사용하지 않음 |
| `renewal_day` | 지점 갱신일 | 작업지시서 상세 표시 |

### `profiles`

- 작업자 계정과 이름을 관리한다.
- `assignments.*_writer_id`가 `profiles.id`를 참조한다.
- 관리자, 직원, 프리랜서 등 접근 권한의 기준으로 사용한다.

### `branches`

- 지점명, 과목, 상품 유형과 운영 상태를 관리한다.
- 자동 생성에서 비활성 지점을 제외하는 기준으로 사용한다.

## 새로 필요한 데이터

### 월 배정안

- 복제 기준 월과 대상 월
- 자동 또는 수동 생성 여부
- 승인 대기·승인 완료·폐기 상태
- 예외 항목과 사유
- 생성·승인 담당자와 시각
- 중복 실행 방지 기준

### 정산 요청

- 작업 월과 작업자
- 요청 당시 업체·역할·수량 스냅샷
- 청구 금액
- 견적서 파일 또는 저장소 URL
- 요청·보완·승인·이체 완료 상태
- 요청·승인·이체 담당자와 시각
- 전달 메모와 보완 사유

작업 결과, 완료 수량, 결과물 링크, 내부 검수 상태는 저장하지 않는다.

## 반드시 합의할 운영 규칙

### 자동 배정

- 자동 생성일
- 직전 승인 월과 별도 기준 배정안 중 복제 기준
- 전체 일괄 승인 또는 부분 승인
- 확인 필요 항목이 남아 있을 때 승인 가능 여부
- 비활성 지점·담당자 처리 방식

### 정산

- 정산 대상이 프리랜서만인지 직원도 포함하는지
- 작업자별 월 1회만 요청할지
- 요청 금액을 직접 입력할지 단가로 자동 계산할지
- 견적서가 필수인지
- 노션에서 미완료가 확인됐을 때 보완 처리 방식
- 결제 담당자를 별도 권한으로 만들지
- 이체 완료 후 누가 다시 열 수 있는지

## 샘플 페이지에서 확인할 것

- 자동 배정안에서 예외 항목만 확인하는 흐름이 충분한지
- 승인된 배정만 담당자에게 표시되는지
- 담당자별 역할 수량과 총합이 기존 대시보드와 같은지
- 배정 내역이 청구 요청 당시 스냅샷으로 저장되는지
- 결제 담당자가 노션 확인 후 청구와 지급을 처리할 수 있는지
- 결제 담당자에게 추가로 필요한 정보가 무엇인지

샘플 페이지의 상태 버튼은 브라우저 메모리만 바꾸며 DB에는 저장하지 않는다.

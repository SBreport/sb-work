# sb-work 업무 배정·정산 기능 기획 초안

> 문서 버전: 0.3  
> 작성일: 2026-08-28  
> 목적: 기획자가 업무 규칙과 화면 흐름을 확정하고, 개발자가 구현 명세로 전환할 수 있도록 범위를 정리한다.

## 1. 기획 배경

현재 `sb-work`는 월별 지점과 담당자의 업무 배정량을 관리한다. 이를 다음 업무까지 연결하려 한다.

```text
월 배정안 자동 생성
→ 관리자 예외 확인·승인
→ 담당자 배정 업무 확인·수행
→ 담당자 월 정산 요청·견적서 제출
→ 관리자가 노션에서 작업 결과 확인
→ 결제 승인
→ 이체 완료
```

업체가 100곳을 넘기 때문에 매월 모든 배정을 다시 입력하는 방식은 유지하기 어렵다. 반복 배정은 자동 생성하고 관리자는 변경되거나 문제가 있는 항목만 확인해야 한다.

작업 결과물은 기존 노션에서 관리한다. `sb-work` 안에는 결과물 링크, 완료 보고, 내부 검수 기능을 새로 만들지 않는다.

## 2. 목표

- 월별 반복 배정 입력을 자동화한다.
- 자동 생성 배정은 관리자 승인 후 담당자에게 공개한다.
- 담당자는 본인에게 승인된 업무만 확인한다.
- 담당자가 월 배정 내역을 기준으로 정산과 견적서를 요청한다.
- 결제 담당자는 노션에서 작업 결과를 확인하고 청구 내역을 승인한다.
- 배정안 승인부터 이체 완료까지 처리자와 처리 시점을 추적한다.

## 3. 범위

### 포함

1. 운영·배정 현황
2. 월 배정안 자동 생성과 승인
3. 담당자 작업지시서
4. 월 정산 요청과 견적서 제출
5. 결제 승인과 이체 완료

### 포함하지 않음

- 결과물 업로드
- 결과물 링크 제출
- 완료 수량 보고
- `sb-work` 내부 작업 검수
- 노션 데이터 연동

노션 연동은 실제 필요성이 확인되면 후속 범위로 검토한다.

## 4. 샘플 페이지 활용 원칙

`sb-settlement-handoff-windows.zip`은 정보 구조와 업무 흐름을 확인하기 위한 프로토타입이다. 최종 디자인을 그대로 복제하지 않고 기존 `sb-work`의 레이아웃과 컴포넌트를 우선한다.

샘플 데이터와 상태는 브라우저에만 저장되며 실제 업무 데이터가 아니다.

## 5. 사용자와 권한

| 사용자 | 주요 업무 | 조회 범위 |
|---|---|---|
| 업무 배정자 | 자동 생성 설정, 배정안 검토·승인, 수동 배정 | 전체 지점과 담당자 |
| 작업 담당자 | 본인 작업지시서 확인, 월 정산 요청 | 본인에게 승인된 업무만 |
| 결제 담당자 | 노션 확인, 청구 보완 요청, 결제 승인, 이체 완료 | 정산 요청 전체 |
| 시스템 관리자 | 사용자 권한과 기준정보 관리 | 전체 |

한 사람이 여러 역할을 겸할 수 있다. 결제 담당자를 기존 관리자 권한으로 처리할지 별도 권한으로 만들지는 기획 단계에서 확정한다.

## 6. 화면별 요구사항

### 화면 1. 운영·배정 현황

#### 상단 요약

- 대상 월
- 전체 예정량
- 승인 배정량
- 미배정량
- 정산 요청 인원
- 지급 완료 인원
- 자동 생성 상태와 다음 생성 예정일
- `자동 생성 설정`, `지난달 기준 배정안 생성`

#### 자동 생성 승인 영역

- 대상 월과 생성 시각
- 전체 업체 수
- 정상 복제 건수
- 확인 필요 건수
- 새 업체, 중단 업체, 미지정 담당자, 수량 변경 건수
- `확인 필요만 보기`, `전체 검토`, `배정안 승인`, `배정안 폐기`

#### 수동 배정

입력 순서는 다음과 같이 유지한다.

```text
지점 → 담당자 → 역할 → 수량
```

#### 지점별 배치 현황

| 표시 정보 | 설명 |
|---|---|
| 지점 | 업체명과 분류 |
| 예정량 | 해당 월 기준 작업량 |
| 담당자·역할·수량 | 역할별 배정 내용 |
| 배정 합계 | 전체 배정 수량 |
| 전월 대비 | 담당자 또는 수량 변경 |
| 상태 | 정상, 미배정, 초과, 확인 필요, 승인 완료 |

관리자가 100개 업체를 모두 확인하지 않도록 `확인 필요` 필터를 우선 제공한다.

### 화면 2. 작업지시서

- 로그인한 담당자의 승인된 업무만 표시
- 업체명, 역할, 배정 수량, 갱신일 표시
- 월 전체 업체 수와 배정량 표시
- 정산 요청 상태 표시
- `이번 달 정산 요청하기` 버튼
- 다른 담당자의 업무는 URL 직접 접근으로도 조회할 수 없어야 함

결과물과 작업 진행 상태는 표시하지 않는다. 담당자는 기존 노션에서 결과물을 관리한다.

### 화면 3. 정산 요청

- 선택한 월의 승인 배정만 청구 대상으로 표시
- 업체별·역할별 수량과 총수량 표시
- 청구 금액 입력 또는 단가 기준 자동 계산
- 견적서 첨부
- 전달 메모
- `배정 업무를 완료했으며 청구 내역이 정확하다`는 확인
- 요청 당시 업체·역할·수량·금액을 스냅샷으로 보존
- 요청 이후 배정이 바뀌면 요청 당시 수량과 현재 수량 차이 표시

### 화면 4. 결제 관리

- 담당자별 정산 요청 목록
- 요청 상태와 요청일
- 요청 당시 수량과 현재 배정 수량 비교
- 역할별 작업량
- 청구 금액과 견적서
- `결과물은 노션에서 확인` 안내
- 보완 요청과 사유
- 결제 승인
- 이체 완료
- 승인자·승인 시각·이체 처리자·이체 시각

이 화면은 작업을 검수하는 곳이 아니다. 결제 담당자는 노션에서 결과를 확인한 후 청구와 지급만 처리한다.

## 7. 월 배정안 자동 생성 규칙

### 권장 기본값

| 항목 | 1차 권장안 |
|---|---|
| 사용 여부 | 관리자가 켜고 끔 |
| 주기 | 월 1회 |
| 생성 시점 | 관리자가 지정한 매월 특정일 |
| 시간대 | Asia/Seoul |
| 대상 월 | 다음 달 |
| 복제 기준 | 가장 최근 승인된 월 배정 |
| 승인 단위 | 대상 월 전체 일괄 승인 |
| 수동 실행 | 허용 |

### 자동 검사

- 운영 중단 또는 비활성 지점
- 비활성·퇴사 담당자
- 담당자 미지정
- 예정량보다 적거나 많은 배정
- 대상 월의 기존 배정
- 같은 지점·역할·슬롯의 중복 배정
- 전월 대비 담당자 또는 수량 변경

### 반영 원칙

- 생성 직후에는 관리자만 볼 수 있는 `승인 대기` 상태로 저장한다.
- 승인 전에는 담당자의 작업지시서와 실제 운영 통계에 포함하지 않는다.
- 확인 필요 항목이 남아 있으면 일괄 승인할 수 없게 하는 것을 기본안으로 한다.
- 승인 시 한 번에 반영하고 승인자와 승인 시각을 기록한다.
- 기존 대상 월 데이터를 자동으로 덮어쓰지 않는다.
- 정산과 결제 기록은 복제하지 않는다.
- 승인 후 수정은 기존 배정 변경 절차와 변경 이력을 따른다.
- 같은 월의 자동 생성은 중복 실행되지 않아야 한다.

지난달의 일회성 변경이 다음 달까지 이어질 수 있다. 1차에는 최근 승인 월을 복제하고, 필요하면 별도 `기준 배정안` 기능을 후속 검토한다.

## 8. 상태 정의

기존 `assignments.status`는 신규·변경·중단·보류 등 지점 업무 상태이므로 아래 상태와 혼용하지 않는다.

### 배정안

```text
생성 중 → 승인 대기 → 승인 완료
                  ↘ 폐기
```

### 정산

```text
요청 전 → 승인 대기 → 결제 승인 → 이체 완료
                   ↘ 보완 요청 → 재요청
```

상태 변경에는 처리자, 처리 시각과 필요한 경우 사유를 기록한다.

## 9. 기존 데이터와 신규 데이터

### 재사용할 기존 데이터

| 데이터 | 사용 목적 |
|---|---|
| `branches` | 지점·업체 정보와 운영 상태 |
| `profiles` | 담당자 계정, 조직, 권한 |
| `assignments` | 월·지점·역할·담당자·수량 |
| `assignment_logs` | 승인 후 배정 변경 이력 |
| `cost_settings` | 단가 자동 계산을 사용할 경우 참고 |

### 새로 필요한 정보

- 자동 생성 설정과 실행 이력
- 생성 대상 월, 복제 기준 월, 배정안 상태
- 예외 항목과 사유
- 배정안 승인자와 승인 시각
- 정산 요청 당시 배정 스냅샷
- 청구 금액, 견적서, 요청 메모
- 정산 상태와 보완 사유
- 승인·이체 담당자와 처리 시각

결과물, 완료 보고, 내부 검수 데이터는 만들지 않는다. 실제 테이블과 컬럼은 개발자가 운영 DB를 확인한 뒤 설계한다.

## 10. 예외 상황

| 상황 | 기본 처리안 |
|---|---|
| 대상 월에 기존 배정이 있음 | 덮어쓰지 않고 충돌 표시 |
| 담당자가 비활성 상태 | 미지정 처리 후 확인 필요 표시 |
| 지점이 비활성 상태 | 자동 생성에서 제외하고 제외 내역 표시 |
| 예정량이 0이거나 없음 | 확인 필요 표시 |
| 승인 전 담당자 변경 | 배정안에서 수정 가능 |
| 승인 후 담당자·수량 변경 | 변경 이력 기록, 담당자에게 변경 표시 |
| 정산 요청 후 배정량 변경 | 요청 스냅샷과 현재 수량 차이 표시 |
| 노션에서 작업 미완료 확인 | 결제 화면에서 보완 요청 |
| 이체 완료 후 수정 요청 | 관리자만 재개 가능하도록 검토 |

## 11. 알림 요구사항

최소한의 서비스 내 알림 대상은 다음과 같다.

- 다음 달 배정안 생성 완료 또는 실패
- 관리자 승인 대기
- 담당자에게 신규·변경 배정 공개
- 정산 요청 접수
- 보완 요청
- 결제 승인
- 이체 완료

이메일·카카오톡 등 외부 알림은 채널과 비용을 확정한 후 별도 범위로 잡는다.

## 12. 완료 기준

- 월 배정안이 지정 주기에 자동 생성된다.
- 관리자는 예외 항목만 필터링할 수 있다.
- 승인 전 배정안은 담당자에게 보이지 않는다.
- 같은 월 배정이 중복 생성되거나 자동으로 덮어써지지 않는다.
- 담당자는 본인에게 승인된 업무만 조회한다.
- 결과물 링크, 완료 보고, 내부 검수 기능이 생성되지 않는다.
- 작업자는 승인 배정을 기준으로 정산을 요청한다.
- 정산 요청 당시 수량과 금액이 보존된다.
- 결제 담당자는 현재 배정과 요청 당시 수량을 비교할 수 있다.
- 노션 확인 안내가 결제 화면에 표시된다.
- 모든 승인과 상태 변경에 처리자와 시각이 남는다.
- 새 데이터에는 역할별 접근 권한이 적용된다.
- 기존 `sb-work` 배정과 대시보드 기능이 유지된다.

## 13. 1차 범위에서 제외할 항목

- 결과물 관리와 노션 자동 연동
- 은행 자동 이체
- 세금계산서 또는 원천징수 자동 처리
- 회계 서비스 자동 연동
- 외부 알림 채널 연동
- AI 자동 배정 최적화
- 복잡한 주·격주 반복 일정

## 14. 기획자가 확정할 질문

### 자동 배정

- 자동 생성일은 매월 며칠인가?
- 복제 기준은 직전 월인가, 별도 기준 배정안인가?
- 전체 월을 한 번에 승인할지 일부 업체만 승인할 수 있게 할지?
- 확인 필요 항목이 있어도 나머지를 승인할 수 있는가?
- 지점별 자동 생성 제외 또는 담당자 고정 설정이 필요한가?
- 승인 후 변경을 담당자에게 어떻게 알릴 것인가?

### 작업지시서

- 배정된 수량과 실제 수행 수량이 다를 때 어디에서 조정하는가?
- 노션 위치를 안내하는 공통 버튼이 필요한가, 별도 연동 없이 안내만 할 것인가?
- 작업자가 정산 요청할 수 있는 시작일과 마감일이 있는가?

### 정산과 지급

- 정산 대상은 프리랜서만인가, 직원도 포함하는가?
- 작업자별 월 1회만 요청할 수 있는가?
- 금액은 직접 입력인가, 단가로 자동 계산하는가?
- 견적서는 필수인가?
- 결제 담당자는 별도 권한인가?
- 노션에서 미완료가 확인되면 전체 요청을 보완 처리하는가, 일부만 조정하는가?
